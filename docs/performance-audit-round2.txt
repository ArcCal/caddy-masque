Changes and invariants
======================
- Reuse a small capsule writer buffer under the existing writer mutex. Retained
  capacity is bounded at 2 KiB; oversized writes are not kept indefinitely.
- Reject a full host-to-client queue before copying the packet. Existing queue
  synchronization and drop semantics remain; global/session counters agree.
- Move the embedded statistics value from the session to its session handle,
  with the session holding a pointer to that value. This lets network-queue
  drops and session logs update/read the same counters; the old statistics
  value was already embedded, so this does not remove a separate allocation.
- Index recent leases by address and maintain release order. Bound incidental
  expiry cleanup to 16 entries per activity; use-time expiry checks remain
  mandatory. Released address slices are immutable while shared by the index.
- Maintain per-user active counts, including dual-stack revocation and late
  release. Reject an already full user quota before pool/conntrack work, then
  recheck under the final allocation lock. Registered state prevents duplicate
  decrements. A 10000-operation model and concurrency/rollback tests cover these
  indexes and counters.
- Limit concurrent password checks to twice the smaller of NumCPU/GOMAXPROCS.
  This avoids excessive work in CPU-constrained processes. The password hashing
  algorithm and cost, constant-time checks and authentication policy are intact.
- Update toolchain 1.26.10 to 1.26.11 and klauspost/compress 1.20.1 to 1.20.2.
  README documents patched minima 1.26.11 or 1.27.4. Patch rustix in the test
  client lock without unrelated Windows dependency downgrades.

The security updates address GO-2026-6859 (HTTP/1 connection-close header race)
and GO-2026-6865 (compression parser panic). Neither change weakens protocol or
security policy. No local HTTP/2 or HTTP/3 fork source was changed. Fork pin and
patch provenance verification passed. No DNSSEC, TLS verification, ownership,
revocation or packet validation bypass was introduced.

Performance evidence
====================
Isolated baseline/candidate capsule-writer and full-queue allocation tests and
benchmarks are preserved as caddy/writer-* and caddy/queue-*; allocation changes
are the primary conclusion, not shared-host timing. Authentication/lease
measurements and candidate pool analysis are retained under the preceding audit
and round-2 artifacts. Recent-lease cleanup now has a deterministic per-activity
work bound; correctness still depends on use-time expiry checks, which remain.

The interval address-pool candidate was rejected: common default-pool operations
regressed 14-52% and fragmented heap use increased 2.87 times. No claim of
improved public-WAN throughput is made from local microbenchmarks.

Limits and reproduction
=======================
Finite tests do not prove all IETF requirements, inputs or schedules. Source
inventory is not a claim of line-by-line review of all vendored upstream code.
Failed/skipped/interrupted commands remain in the evidence directory and do not
count as passes. The final suite results above supersede earlier incomplete runs.
Native macOS framework/UI/PF behavior, code signing, ARM runtime and live public
WAN/Cloudflare behavior were unavailable. No claim of zero possible regressions
or universal speedup is made.

Use the patched Go toolchain with GOTOOLCHAIN=local; full validation used
GOMAXPROCS=2 and -p 2. Run maintained root, HTTP/2 security and transport fork
test entry points; use MASQUE_CLIENT to enable CLI interop. Root-only tests need
an isolated TUN/nftables environment. The local environment/run-kernel.sh avoids
host networking and host firewall changes. Complete outputs, scratch overlays,
source hashes, binaries and immutable-client matrix hashes are retained under
the evidence root. Companion details are in masque-vpn's
docs/validation/performance-audit/round2-local-audit.txt.
