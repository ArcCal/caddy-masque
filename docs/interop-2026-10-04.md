**MASQUE interoperability and production validation — 4 October 2026**

HTTP/3, HTTP/2 and HTTP/1.1 CONNECT-IP remain supported. The modified Rust MASQUE VPN client passed all 21 primary Caddy matrix cases and two additional refusal cases against this checkout based on `67cd06647f197eca8333608e134993d79168ac63`. The Rust validation baseline is `ba82e36164a69c01a2a366153550aee2821c41b7`. This report accompanies the tested changes; no production deployment occurred. The priorities remain IETF compatibility, own Rust pair compatibility, then Rust/Caddy interoperability.

The real-kernel Rust suite passed 182 checks with no failures or skips, and the shipped systemd units passed all 37 checks. Ten optimized Rust-client/Caddy HTTP/2 load runs passed 260 checks, transferring 1 GB down and 500 MB up without unexpected reconnects. The final Caddy kernel replay passes all 229 checks with zero failures/skips and a clean launcher exit; the separate adverse-network replay passes 38 checks. Both use fixed shell inputs. A real-kernel Packet Too Big test also passes 17 checks and verifies UDP recovery after learning the path MTU. Unlike the previous evaluation, the managed Docker daemon provides real TUN, namespace, nftables, routing and NAT access in isolated containers.

A production HTTP/2 failure was traced to Rust h2's small-DATA-frame overhead budget. Both Rust endpoints now retain bounded 1 MiB framing budgets, payload flow control and empty-frame protection. No transport or protocol feature was removed. Malformed HTTP/2 messages use `PROTOCOL_ERROR` (1) and HTTP/3 uses `H3_MESSAGE_ERROR` (270), with unrelated streams continuing to work. Both capsule decoders include the complete IPv6 header in their default limits; Rust discards oversized DATAGRAM capsules without aborting the stream. IPv6 all-nodes MTU probes receive local unicast replies. The service no longer dumps its environment into the journal.

Rust full-tunnel routing now resists injected public DHCP routes while preserving private and directly connected LAN access; scoped behavior is retained. Proxy DNS addresses refresh before reconnection through marked bootstrap queries outside a broken system tunnel. Kernel tests verify address changes over all three transports with TLS hostname checks enabled. Reconnect jitter, website symlink confinement and locked Rust builds are also implemented. These fixes supersede the previous report's unresolved public-route bypass and startup-only DNS findings; intentional LAN exceptions remain.

Rust recorded 214 passing tests. Go recorded 162 passing test/subtest events, including 143 top-level cases, with the race detector. Three nftables subtests skipped outside Docker and all three passed with kernel access. Vet, module checks, fork verification and the complete upstream HTTP/2/HPACK race suites pass. Capsule segmentation fuzzing completed 344,203 executions without failure. The independent wire gate passed all 12 targeted malformed-input checks. Bundled Caddy, xcaddy and the pinned Cloudflare variant build successfully. Fresh audits found zero Rust vulnerabilities and no reachable vulnerable Go functions; dependency maintenance/module advisories remain recorded in the full report. Stripped binary scans cannot establish full symbol reachability and retain the legacy OpenPGP advisory at module precision; the primary source import graph excludes that package.

Adverse-network tests measure real loss and throughput, check checksums, verify a 4 Mbit/s aggregate software rate limit, and exercise 20-second and 70-second outages. UDP capacity checks use 1200-byte application payloads within the guaranteed 1280-byte tunnel path and require receiver data. The failed auto-sized UDP trial is retained; large packets depend on path MTU and application PMTU handling. CI builds the optimized Rust client, explicitly passes the simulator and runs bounded capsule fuzzing.

Go 1.26.8 and Caddy 2.11.6 are validated. The pinned x/net v0.59.0 reset patch remains required. External main modules must explicitly replace x/net with `third_party/xnet`; Go does not inherit dependency replacements. See [patch maintenance instructions](../third_party/README.md). Go or x/net upgrades require the reset and interoperability gates again.
